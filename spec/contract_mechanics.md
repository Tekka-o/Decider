# 契約書査定ゲーム 仕様書 - 契約書・査定ルール仕様 (contract_mechanics.md)

本ドキュメントは、プレイヤーが査定する「契約書」の文面要素、正誤（利と不利）の判定基準、および間違い探しの照合ルールについて定義します。

---

## 1. 契約書の基本項目と照合基準

契約書を構成する各要素は、デスク上の「マニュアル」や「時計・カレンダー」と見比べることで、正誤の判定が可能です。

| 契約書内の項目 | チェック対象 | 照合するガジェット / ルール |
| :--- | :--- | :--- |
| **自社名** | テキスト表記、ロゴ | **マニュアル**: 自社の正確な名称（例: 『株式会社ネクストリンク』）と一致しているか。 |
| **取引先名** | テキスト表記 | **マニュアル**: 取引先リストに存在する実在の会社名か。 |
| **契約日付** | 年月日 | **時計・カレンダー**: 「4月10日」から1日ずつ進むカレンダーの日付と完全一致、もしくは現実的な範囲内か（明らかに過去、または未来の日付は不備）。 |
| **契約本文** | 条文、金額、役割（甲・乙） | **マニュアル・ビジネス常識**: 日本語の崩れ（ひらがな、タメ口）がないか。前後の条文で金額や条件に矛盾がないか。 |
| **裏面・注釈** | 隠された条項、極小文字 | **裏面確認**: 表面にないデメリット条項（極小文字での不利な契約）が追記されていないか。 |

---

## 2. 査定判定のルール定義

プレイヤーは、**「不備が1つもない完璧な契約書」のみを【承認】**し、**「不備が1つでもある契約書」は【破棄】**しなければなりません。

### 2.1. 【承認】の条件
* 契約書の全項目が、マニュアル、カレンダーの情報と完全に合致している。
* 文脈に矛盾がなく、ビジネス文書として適切な言葉遣い（敬体）で書かれている。
* 裏面に悪質な条項（極小文字の罠など）が記載されていない。

### 2.2. 【破棄】すべき不備・罠のパターン（間違い探しのバリエーション）

#### ① 会社名の間違い（マニュアル照合）
自社名や相手企業の名称が、1文字だけ、あるいは微妙に異なっている。
* *自社名間違い例*: 
  * 正: 『株式会社ネクストリンク』
  * 誤: 『株式会社ネクス**トト**リンク』(文字の重複)
  * 誤: 『株式会社ネクスト**リング**』(濁点の有無)
* *取引先名間違い例*:
  * 正: 『東都商事株式会社』
  * 誤: 『東**京**商事株式会社』

#### ② 日付の異常（カレンダー照合）
デスク上の日付（4月10日から始まるその日の日付）と照合した際、あり得ない時期になっている。
* *過去の例*: 今日の日付（ゲーム上のカレンダー）が「4月12日」なのに、契約書の日付が「1998年4月1日」など、あからさまに古い。
* *未来の例*: 今日の日付が「4月12日」なのに、契約書の日付が「2126年12月31日」など、遠い未来になっている。

#### ③ 口調の乱れ・ビジネス文書としての崩れ
敬語が使われていなかったり、ひらがなばかりで書かれている。
* *ひらがな表記*: 
  * 「けいやくしょ。こうとおつは、なかよく仕事をすることをここにちかいます。」など、すべてひらがなで作成されている。
* *タメ口（カジュアル）表記*:
  * 「第1条: 成果物は今週末までに提出してね！」「第2条: 報酬はちゃんと払うから安心してよね」などのフランクな口調。

#### ④ デメリットをメリットのように見せる偽装（悪意ある契約）
一見すると素晴らしい好条件のように見えて、別の箇所や裏面でそれを覆す罠。
* *偽装メリット*:
  * 表面:「※本システムは初期費用および月額料金を永年無料とする」
  * 裏面（極小文字）:「※ただし、本システムを利用した取引1回につき、50％の手数料を自社が徴収するものとする」
* *文脈の矛盾*:
  * 表面第3条:「甲は乙に対し、報酬として金50万円を支払う」
  * 表面第7条:「乙は、第3条に定める支払額100万円を受け取った後……」 (金額が矛盾している)

## 3. 契約書の重要度（難易度）と出現確率
契約書には、ミスのペナルティに関わる「重要度（難易度）」が設定されています。インゲーム中、部下が提出してくる契約書の重要度別出現確率は以下のように設定され、難易度が高い契約書に偏らない設計となっています。

* **重要度【低】**: 出現確率 **60%**
* **重要度【中】**: 出現確率 **35%**
* **重要度【高】**: 出現確率 **5%**
